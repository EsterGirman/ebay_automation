# eBay E2E Automation (Playwright + Pytest + POM + Allure)

תרחיש E2E על eBay: חיפוש מוצרים עם תנאי מחיר (כולל Paging), הוספה לסל עם בחירת וריאנטים
אקראית, ואימות שסכום הסל לא עולה על התקציב.

## מיפוי דרישות התרגיל לקוד

| דרישה | היכן |
|---|---|
| הזדהות | `EBayWorkflowService.authenticate` → `pages/login_page.py` |
| חיפוש לפי query | `SearchResultsPage.search` |
| שימוש בפילטר המחיר שבעמוד | `SearchResultsPage._apply_price_filter_ui` (גיבוי: אותו פילטר דרך הכתובת) |
| שליפה ב-XPath של פריטים ≤ maxPrice | `ITEM_CONTAINER` / `ITEM_LINK` / `ITEM_PRICE` ב-`search_results_page.py`, סינון ב-`utils/parsing.filter_cards` |
| Paging עד limit או סוף העמודים | `EBayWorkflowService.search_items_by_name_under_price` + `SearchResultsPage.go_to_next_page` |
| החזרת עד limit כתובות (גם 0 תקין) | `search_items_by_name_under_price` מחזיר `List[str]` |
| addItemsToCart: לולאה, פתיחת פריט, וריאנטים אקראיים, Add to cart, חזרה ללשונית החיפוש (פריט שנכשל מוחלף ברזרבי) | `EBayWorkflowService.add_items_to_cart` → `ItemDetailsPage.add_to_cart` |
| צילום מסך ו-Log לכל פריט | `item_<n>_added_to_cart.png` / `item_<n>_add_failure.png` (פריט רזרבי: `spare_<n>_...`) + שורת לוג לכל פריט |
| assertCartTotalNotExceeds: פתיחת הסל, קריאת הסכומים, סף, אימות (פענוח ב-`utils/parsing.parse_cart_summary`) | `EBayWorkflowService.assert_cart_total_not_exceeds` → `CartPage.assert_total_not_exceeds` |
| (תוספת) אימות שהפריטים באמת בסל: מספר ב-Order summary + מזהי הפריטים | `EBayWorkflowService.assert_items_in_cart` → `CartPage.assert_contains_items` |
| Screenshot/Trace של עמוד הסל | `cart_page.png` + Trace מלא של התרחיש (`--tracing=on`) |
| POM / OOP | `pages/` – מחלקה לכל עמוד, ירושה מ-`BasePage` |
| Data-Driven מקובץ חיצוני | `config/test_data.json` → `utils/config.load_scenarios` → `pytest.mark.parametrize` |
| דוחות | Allure (`allure-results/`), כולל צעדים, צילומים, Trace ופרטי סביבה |

## התקנה (PyCharm)
1. File > Open > תיקיית הפרויקט. Virtual Environment עם Python 3.9+.
2. `pip install -r requirements.txt`
3. נדרש Google Chrome מותקן (הבדיקה רצה בערוץ `chrome` של Playwright).

## הרצה
    pytest                    # הכול
    pytest -m "not e2e"       # בדיקות unit בלבד (שניות, בלי דפדפן)
    pytest -m e2e             # התרחיש מול האתר
    allure serve allure-results   # דורש Allure CLI מותקן (https://allurereport.org/docs/install/)

ברשת איטית או מסוננת הרצת E2E אורכת כ-10 דקות (רוב הזמן: בדיקות הבוט של eBay וטעינת עמודים).

תוצרים: צילומי מסך ב-`reports/screenshots/` (התיקייה מתרוקנת בתחילת כל הרצת E2E, כדי שלא יתערבבו
צילומים מהרצות קודמות), Trace וצילום בכישלון ב-`reports/test-results/`
(`playwright show-trace <path>/trace.zip`). הכול מצורף גם לדוח Allure.

## התחברות
פרטי ההתחברות מגיעים **רק** ממשתני סביבה (ב-PyCharm: Run > Edit Configurations > Environment variables):

| משתנה | תפקיד |
|---|---|
| `EBAY_USER`, `EBAY_PASS` | חשבון בדיקות ייעודי. בלעדיהם התרחיש רץ כאורח (eBay מאפשרת סל לאורחים) |
| `EBAY_LOGIN_WAIT_SEC` | זמן להשלמה ידנית של CAPTCHA / קוד אימות בחלון (ברירת מחדל 120) |
| `EBAY_REQUIRE_LOGIN` | `1` כדי שהתחברות שלא הושלמה תכשיל את הטסט (ברירת מחדל: ממשיכים כאורח) |
| `EBAY_BLOCK_IMAGES` | `0` כדי לטעון תמונות (ברירת מחדל: חסומות, לטעינה מהירה) |
| `EBAY_KEEP_CART` | `1` כדי להשאיר את הסל בסוף הטסט לבדיקה ידנית (ברירת מחדל: מתרוקן) |

אחרי התחברות מוצלחת מצב ההתחברות נשמר ב-`.auth/ebay_state.json` (מחוץ ל-git) ונטען בהרצות הבאות,
כך שמסך ההתחברות לא מופיע בכל הרצה. ההתחברות מאומתת מול עמוד שדורש התחברות מלאה (My eBay),
כי eBay מזהה גם סשן ישן ועדיין דורשת סיסמה לפני פעולות סל. אם הסיסמה נדרשת שוב באמצע התרחיש
(“Welcome back”), היא מוזנת אוטומטית. כדי להתחיל מחדש: למחוק את `.auth/`.

**CAPTCHA ואימות זהות:** אם eBay מציגה CAPTCHA או מבקשת קוד אימות (למייל/SMS, `accounts.ebay.com/.../stepup`),
הטסט ממתין (`EBAY_LOGIN_WAIT_SEC`) שיושלמו ידנית בחלון, ואז ממשיך. לחיצה שלא נקלטה (עמוד שנטען לאט
וכפתור שעוד לא פעיל) חוזרת אחרי 15 שניות. מעבר לעמוד ה-CAPTCHA **אינו** נחשב התחברות: ההצלחה מאומתת מול My eBay,
ורק אז מצב ההתחברות נשמר לקובץ. חסימת התמונות (`EBAY_BLOCK_IMAGES`) לא חלה על מסכי ההתחברות
וה-CAPTCHA, כי האתגר בנוי מתמונות. **המשך כאורח:** אם ההתחברות לא הושלמה בזמן (CAPTCHA או קוד שלא הוזנו, למשל כשסינון תוכן ברשת חוסם
את תמונות האתגר), הטסט **ממשיך כאורח**: מנקה את העוגיות של הסשן החלקי, מוחק את `.auth/`, כותב
אזהרה בלוג ומסמן בדוח Allure `auth = guest (sign-in fallback)`. eBay מאפשרת סל לאורחים ושאר התרחיש
לא תלוי בחשבון, כך שהבדיקה נשארת מלאה. מי שרוצה שהתחברות תהיה חובה מגדיר `EBAY_REQUIRE_LOGIN=1`.

## Data-Driven
`config/test_data.json` מכיל רשימת `scenarios`; כל תרחיש הופך להרצה נפרדת של הטסט:

| שדה | משמעות |
|---|---|
| `search_query`, `max_price`, `limit` | הקלט של `search_items_by_name_under_price` |
| `budget_per_item` | התקציב לפריט באימות הסל |
| `currency` | המטבע של המחירים והתקציב. פריטים במטבע אחר מדולגים, כי אי אפשר להשוות ש"ח לדולר |
| `max_pages` | מספר עמודי תוצאות מקסימלי ל-Paging |

## ארכיטקטורה
ארבע שכבות, וכל שכבה מכירה רק את זו שמתחתיה:

```
tests/      הטסט קורא כמו התרחיש בהנחיות; fixtures: דפדפן, context, ניקוי סל (teardown)
services/   התהליך העסקי: ארבע הפונקציות של התרגיל, מעל ה-Page Objects
pages/      Page Object לכל עמוד: לוקייטורים + פעולות של העמוד בלבד
utils/      לוגיקה טהורה (פענוח מחיר/מטבע/סל) + טעינת נתונים - בלי דפדפן, עם בדיקות unit
config/     test_data.json - קלטי הבדיקה (Data-Driven)
```

- `pages/` – `HomePage`, `LoginPage`, `SearchResultsPage`, `ItemDetailsPage`, `CartPage`, כולם יורשים
  מ-`BasePage` (ניווט עמיד, זיהוי חסימה, צילומי מסך, חלונות קופצים). הלוקייטורים הם קבועי XPath
  בראש כל מחלקה, חוץ מחלון המיקום שמוזרק דינמית (טקסט/role).
- `services/ebay_workflow_service.py` – `authenticate`, `search_items_by_name_under_price`,
  `add_items_to_cart`, `assert_cart_total_not_exceeds`, ובנוסף `clear_cart` ו-`assert_items_in_cart`.
  שירות אחד, כי זה תהליך עסקי אחד; פיצול ל-AuthService/CartService נכון כשיש כמה תהליכים.
- הטסט לא מכיר XPath, כפתורים או דוחות: שינוי ממשק של eBay מתוקן ב-`pages/` בלבד.

## החלטות תכנון

### חיפוש ופילטר מחיר
- **"Buy It Now" בלבד:** פריט במכירה פומבית לא ניתן להוספה לסל, לכן החיפוש מוגבל לקנייה מיידית.
- **פילטר המחיר שבעמוד** (סרגל הצד) מופעל קודם, כנדרש. שלוש התנהגויות של eBay מטופלות:
  - הלוקייטור מכוון לשדה הטקסט בלבד: לסליידר המוסתר של גרף המחירים יש אותה תווית.
  - המחיר מוקלד תו-תו (`press_sequentially`) ולא ב-`fill`: הרכיב לא קולט ערך שהודבק בבת אחת,
    וההקלדה הראשונה רק "מעירה" אותו. מקלידים שוב עד שהחץ הופך פעיל (עד 3 פעמים).
  - הלחיצה על החץ מקפיצה לפעמים את חלון המיקום; אישורו טוען את העמוד מחדש והפילטר אובד.
    eBay שואלת פעם אחת, לכן אחרי אישור המיקום מפעילים את הפילטר שוב (עד 2 ניסיונות).
- **גיבוי:** אם הפילטר שבעמוד לא נקלט, **אותו פילטר של eBay** מוחל דרך הכתובת (`_udhi`), עם אזהרה
  בלוג. התוצאה זהה; הגיבוי קיים כדי ששינוי ממשק של eBay לא יפיל את כל התרחיש.
- **XPath בקריאה אחת:** כל כרטיסי התוצאות נשלפים בקריאה אחת לדפדפן (XPath יחסי לכל כרטיס),
  מהיר בהרבה מלולאה של קריאות לכל כרטיס.
- **טווח מחירים** ("ILS 100 to ILS 300") נחשב לפי הערך הגבוה, כדי שבחירת וריאנט אקראי לא תחרוג.
- **מטבע:** eBay מציגה מחירים לפי מיקום הגולש (מישראל: ILS, גם לפריטים שנמכרים בדולר).
  פריט במטבע שונה מ-`currency` מדולג (נספר ב-`other_currency` בדוח החיפוש). אין המרת מטבע:
  שער משתנה ותלות בשירות חיצוני היו הופכים את הטסט ללא יציב.

### הוספה לסל ואימות
- **הסל מתרוקן לפני התרחיש:** פריטים מהרצות קודמות היו מנפחים את הסכום.
- **כמות 1 לכל פריט:** "וריאנטים אקראיים" חלים על מידה/צבע; כמות אקראית הייתה מכפילה את המחיר
  ושוברת את חישוב הסף. אפשרויות שאזלו ("Out of stock") לא נבחרות.
- **אישור הוספה לפי דומיין:** ההצלחה נבדקת לפי הודעת "Added to cart" או מעבר ל-`cart.ebay.com`,
  ולא לפי המילה cart בכתובת (כתובת מסך ההתחברות מכילה `ru=...cart.ebay.com`).
- **פריט שלא ניתן להוסיף** (אזל, בורר חובה, כפתור לא פעיל) נרשם בלוג ובצילום מסך **ומוחלף**
  בפריט רזרבי. החיפוש מחזיר עד `limit` כתובות כנדרש, ושומר בצד (`spare_urls`) עד `limit` מועמדים
  נוספים מאותם עמודים, בלי דפדוף נוסף. הטסט מוודא שבסל בדיוק מספר הפריטים שהחיפוש החזיר.
- **אימות שהפריטים בסל:** אישור "Added to cart" בדף הפריט לא מספיק. בסוף בודקים בסל עצמו שמספר
  הפריטים ב-Order summary שווה למספר שנוסף, ושכל מזהה פריט (`/itm/<id>`) שנוסף מופיע בסל.
- **ניקוי בסוף (rollback):** ה-fixture `ebay` מרוקן את הסל ב-teardown גם כשהטסט נכשל, כדי שחשבון
  הבדיקות יישאר נקי. צילום הכישלון נלקח **לפני** הניקוי, וכישלון בניקוי לא הופך טסט שעבר לכישלון.
- **משלוח:** פילטר המחיר של eBay והסינון שלנו הם לפי **מחיר הפריט, ללא משלוח**. לכן אימות הסל
  משווה את שורת `Items (n)` ולא את `Subtotal` (שכולל משלוח); כל הסכומים (פריטים, משלוח, Subtotal)
  מצורפים לדוח. בדיקה כולל משלוח הייתה נכשלת גם כשכל פריט עומד בתנאי.
- **מטבע הסל:** אם הסל מוצג במטבע שונה מהתקציב, האימות נכשל מיד עם הודעה שמסבירה מה לתקן
  בקובץ הנתונים (fail fast), במקום להשוות סכומים במטבעות שונים.

### יציבות מול אתר אמיתי
- **בלי `sleep` קבוע:** המתנה לאלמנטים ולמצבים; טעינה חלקית מטופלת בגלילה, המתנה ורענון.
- **כניסה דרך דף הבית:** דפדפן חדש שנכנס ישר לעמוד פנימי (כמו הסל) מקבל מ-eBay
  "Something went wrong" עד שנוצרות עוגיות הבסיס של האתר. כך גם משתמש אמיתי נכנס.
- **שגיאות רשת** (`net::ERR_ABORTED` – ניווט שנקטע ע"י הפניה של האתר או סינון ברשת) מקבלות
  ניסיון חוזר אחרי המתנה קצרה, במקום להפיל את הטסט.
- **עמוד חסימה** ("Something went wrong", "Pardon our interruption") מזוהה, מצולם, ומקבל ניסיון חוזר
  אחד; אם נמשך – `SiteBlockedError` עם הסבר (רענון חוזר לא עוזר במקרה כזה).
- **בדיקת דפדפן של eBay** ("Checking your browser") עוברת לבד, בין שניות לכ-3 דקות; ממתינים לה
  (עד 3 דקות) ולא נכשלים. בזמן ההפניה העמוד ריק לרגע, לכן הבדיקה נעשית בלולאה מצד Python.
- **חלון המיקום** ("Are you shipping to…?") מאושר אוטומטית בכל עמוד ולשונית
  (`BasePage.install_popup_handlers`, באמצעות `add_locator_handler` של Playwright). הלוקייטור הוא
  טקסט/role ולא XPath, כי החלון מוזרק דינמית; הלחיצה מוגבלת בזמן כדי שלא תתקע את הטסט.
- **מעבר עמוד:** ממתינים לשינוי הכתובת אחרי לחיצה על "Next"; אחרת העמוד הקודם נקרא שוב.
- **שגיאות ברורות:** `SiteBlockedError`, `SignInRequiredError`, `ItemNotAddedError` – כל כישלון מסביר
  מה קרה ומה לעשות, עם צילום מסך, ולא timeout כללי.

### זיהוי בוט
- Chrome אמיתי ומוצג, בלי דגל האוטומציה (`AutomationControlled`), וקצב משתנה (2–5 שניות) בין פריטים.
- CAPTCHA לא נעקפת; אם מופיעה, ממתינים להשלמה ידנית בחלון (`EBAY_LOGIN_WAIT_SEC`).
- הרצות רבות ברצף מגבירות את בדיקות הבוט של eBay; מומלץ להמתין כחצי שעה בין סדרות הרצה.
  ברשת עם סינון תוכן (כגון NetFree) הטעינה איטית יותר וחלק מהתמונות נחסמות.

## הוכחת הרצה
צילומי מסך מהרצות שעברו נמצאים ב-[`evidence/`](evidence/), תיקייה לכל הרצה: פלט ההרצה (`1 passed`),
תוצאות החיפוש אחרי פילטר המחיר, כל פריט שנוסף לסל, עמוד הסל עם הסכומים, ודוח Allure.
(`reports/` ו-`allure-results/` לא נשמרים ב-git: הם נוצרים מחדש בכל הרצה.)
